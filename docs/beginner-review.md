# 초보자 관점 검토

2026-10-11 기준. 문서를 코드와 대조하고 기존 Ubuntu 22.04 가상 검증 환경에서 명령을 재현했다. 실제 초보자가 장비 앞에서 따라 한 사용자 테스트는 아니다. 배포 시 최신 변경이 커밋되는 것을 전제로 검토했다.

**판정:** 가상 데모와 Python 작업 확장의 안내/실행은 확인했다. 실물 연결부터 보정/집기까지 혼자 완료할 수 있다고 검증한 상태는 아니다. 새 Ubuntu 최초 설치와 실제 장비 확인이 남았다.

## 발견한 설명 누락과 보완

| 막히는 지점 | 보완한 내용 |
|---|---|
| 읽을 문서와 실행 순서가 흩어짐 | README 첫 링크와 [처음 사용하기](getting-started.md). 단계별 성공 기준 |
| Control IP를 모르는데 Control 연결부터 시작 | 팔 X5/DHCP/Desk 최초 접속 → Shop Floor IP → Control LAN 전환 |
| LED와 PC 점검만으로 로봇 준비 완료라고 생각할 수 있음 | 색/점멸과 Desk의 상태 확인, doctor의 검사 범위 구분 |
| 공식 구성과 프로젝트 API의 관계가 모호함 | 공식 franka_ros2가 연결/제어 기반이며 Python Robot은 작업용 편의 API임을 명시 |
| 구글 문서에 집기가 추가 개발로 남아 있음 | 현재 클릭 집기 기능, 입력, 실행 여부, 수정 위치 반영 |
| 새 작업 파일/워크스페이스의 구체적인 작성 방법 없음 | Python 파일 복사/source/실행, ament_python 패키지 생성/빌드/진입점 안내 |
| 작업대 높이와 좌표계가 혼동될 수 있음 | 베이스 기준 Z, 독립 실측, 입력 범위와 Z=0 작업면 제한 |
| 두 번째 클릭 작업이 같은 Scene ID로 거부됨 | 한 번 완료 후 서버/장면을 다시 준비하는 절차와 오류 표 |

## 이번 실제 검사

| 항목 | 결과 |
|---|---|
| `doctor.sh --camera` | 실행 파일, Python/Grasp/보정 import, 영상 ABI와 카메라 launch 점검 PASS. 장치 접속 없음 |
| 설치 진입점 | 9/9 PASS. 시스템 설치 대신 명령을 대체해 옵션/실패 차단 검사 |
| 카메라 설치 분기 | 5/5 PASS. 실제 apt/USB 변경 없는 분기 검사 |
| 가상 팔/손 smoke, 도메인 146 | exit 0. SEQUENCE COMPLETE, 9개 관절/ready/한 발행자, 폭 0.04001527 m 확인 |
| 새 ROS2 작업 패키지 | 임시 독립 폴더의 생성/빌드/console entry 검색 PASS |
| 새 패키지의 실제 상태 조회, 도메인 147 | ros2 run fr3_tasks read_state 성공. 팔 7개와 손 2개, STATE READ COMPLETE. 이동/FCI 없음 |

새 패키지의 첫 추가 상태 조회 시도는 함께 사용하던 smoke 서버가 종료된 후 실행되어 parameter service timeout으로 실패했다. 서버를 먼저 시작하고 준비 완료를 기다린 독립 도메인에서는 성공했다. 문서에 서버 A를 유지할 것과 두 번째 서버를 시작하지 않을 것을 명시했다.

합성 보정, CV 창/작업 스레드와 클릭 집기 전체 단계는 앞선 검사에서 통과했으며 이번에는 관련 입력/명령과 문서를 대조했다. 이번 문서 수정 때문에 전체 집기를 다시 실행하지는 않았다. 상세 기록은 [validation.md](validation.md)에 있다.

## 남은 검증

| 필요한 현장 검사 | 현재 상태 |
|---|---|
| 새 native Ubuntu 22.04에서 전체 최초 설치 | 미검증. 기존 ROS 환경 재설치와 분기 검사가 대신할 수 없음 |
| RT/네트워크/Desk/FCI, 실제 팔과 Hand 움직임 | 미검증 |
| D435i 실제 영상, 손눈 보정 정확도 | 미검증. 별도 실측점과 여러 팔 자세에서 확인 필요 |
| 실제 물체의 집기/유지/제자리 놓기/정지 | 미검증. Fake의 붙임/분리로 증명할 수 없음 |
| 초보자의 문서만으로 현장 재현 | 미검증. 교육받은 담당자와 함께 단계별 관찰 필요 |

MoveIt의 종료 segmentation fault(exit -11)는 이번 가상 서버에서도 재현됐다. 이동/조회 성공과 정상 종료는 구분한다. 새 RT 커널 설치나 실물 기능을 자동으로 실행해 이 검토를 진행하지 않았다. 설치부터 실물 보정/집기까지 5분 완료를 보장하지 않는다.

새 워크스페이스 검사는 `bash tests/check_task_workspace.sh`로 재현한다. 실행 중인 **가상 서버**의 상태도 읽으려면 서버와 같은 ROS_DOMAIN_ID에서 `bash tests/check_task_workspace.sh --live`를 사용한다. 이 검사는 임시 작업 폴더만 만들고 정리한다.
